# Palm Pilot

**A touchless interface for AI coding agents — you gesture over the phone, a real model answers.**

Your hand over the top edge of the phone is the only input. No taps, no swipes, no
screen contact: the ambient-light sensor sees the room go dark for as long as your palm
is there, and how long — and how many times — it stays dark is the gesture.

Every line the app shows is generated by `particle-1` while you watch, and the `/REPO`
tab reads a real GitHub repo over the network before it asks the model anything. There
is no scripted content and no fallback copy: no key, no GitHub token, or a bad reply
means you see an error, not a joke.

## The four modes

| Tab | The joke | Gestures |
|---|---|---|
| **LGTM** | You approve everything your agent proposes without reading it | wave = approve · double = auto-approve loop · hold = deny · holdLong = new session |
| **/COMPACT** | Compaction quietly destroys the context you spent an hour building | wave = compact a fact · double = re-seed · triple = three compactions in a row · hold = pin |
| **PANIC** | The agent is stuck and will never know why | wave = next line · double = two turns · triple = four turns · hold = abandon |
| **/REPO** | The agent triages your actual backlog | wave = next pick · double = plan it · triple = roast the repo · hold = refresh from GitHub · holdLong = standup from real commits |

Each action is one model call, printed with its real latency and token count.

## Five gestures, one sensor

| Gesture | How you do it | Event |
|---|---|---|
| wave | quick pass, under 0.7 s | `wave` |
| double | two passes, both inside a 1.5 s window | `double` |
| triple | three passes in the same window | `triple` |
| hold | hand parked ≥ 0.9 s | `hold` |
| holdLong | same hand, kept there past 2.4 s | `holdLong` |

Taps are held back for 240 ms before they are named, which is what lets a third pass
turn a double into a triple instead of firing two events. `hold` and `holdLong` are a
single gesture that escalates: LGTM denies at 0.9 s and resets the whole session if you
simply don't move your hand.

## Why ambient light

The obvious sensor for "hand near the phone" is the IR proximity sensor — the one that
turns the screen off during a call. It is not available:

| Route | Verdict |
|---|---|
| `expo-sensors` `LightSensor` | ✅ works in Expo Go on Android, no native build |
| `expo-sensors` `ProximitySensor` | ❌ does not exist in Expo's SDK |
| `DeviceMotion` / `Accelerometer` | ⚠️ detects the *phone* moving, not a hand over it |
| Camera + MediaPipe hands | ❌ heavy, needs permissions, kills the battery, and you have to point the phone at yourself |
| Native IR proximity | ⚠️ needs a dev build and a community module |

So the input signal is illuminance. A palm 2 cm above the sensor drops lux by ~90%; a
cloud or a lamp fade drops it by ~10%. That difference is the entire problem, and
`src/waveDetector.ts` is the answer to it.

Samsung Galaxy S24 Ultra (`SM-S928`) is the demo target: Android + Expo Go + a light
sensor next to the earpiece. On iOS `expo-sensors` has no `LightSensor` at all, so the
readout stays at `0` and you drive the app with `EXPO_PUBLIC_DEBUG_GESTURES=1`.

boundary is testable without the one before it.

Two rules make this hold together:

1. **Nothing above the bus knows a screen exists.** The detector emits events; the bus
   hands them to exactly one mounted consumer.
2. **Nothing in the UI invents content.** Every screen renders either a real model
   reply or an error object. A validator that cannot accept the reply throws, and the
   screen shows `✕ <reason> · tap to retry`.

## How the detector works

`LightSensor` gives you illuminance only — no direction, no distance. A wave is
therefore a *duration and count* problem, not a trajectory problem. Four decisions make
it usable in a real room:

**1. Learn the room, don't assume it.** The baseline is a slow EMA of ambient light, so
a lamp changing or a cloud passing never looks like a hand.

**2. Hysteresis, or you get dozens of events per wave.** Covering must cross 50% of
baseline; releasing must cross 75%. That gap is what stops a hand hovering at the
threshold from chattering.

**3. Defer naming a tap.** A tap is *counted immediately* but *classified* only after
240 ms of hand-away time. That is what allows a third pass to turn a double into a
triple instead of firing two wrong events.

**4. Escalate a hold instead of adding a gesture.** `hold` fires at 0.9 s, `holdLong`
at 2.4 s — same motion, two meanings, so "deny… no, undo it" needs no extra movement.

`LightSensor` fires every 80 ms. A drop below `max(1.5, baseline × 0.5)` is *covered*;
classification happens on release:

- covered < 700 ms → a **tap** (1 = wave, 2 = double, 3 = triple, inside 1.5 s)
- covered ≥ 900 ms → **hold**; still covered at 2.4 s → **holdLong**
- 700–900 ms → deliberately silent

```ts
// src/waveDetector.ts — release path
if (value > Math.max(1.5, this.base * releaseRatio)) {
  this.covered = false;
  const dur = now - this.coverStart;
  const announced = this.holdEmitted;
  this.holdEmitted = null;

  // tick() may already have announced the hold while the hand was still there
  if (announced) {
    this.clearPending();
    return out;
  }

  if (dur >= holdMs) {
    this.clearPending();
    out.push(dur >= longHoldMs ? 'holdLong' : 'hold');
    return out;
  }

  // Too slow to be a tap, too fast to be a hold: a lazy hand, ignored.
  if (dur > maxWaveMs) {
    this.clearPending();
    return out;
  }

  if (this.taps.length > 0 && now - this.taps[0] <= tapWindowMs) this.taps.push(now);
  else this.taps = [now];
  this.pendingAt = now;
}
```

```ts
// src/waveDetector.ts — tick(): names deferred taps, escalates holds
if (this.covered) {
  const held = now - this.coverStart;
  if (held >= longHoldMs && this.holdEmitted !== 'holdLong') {
    this.holdEmitted = 'holdLong';
    this.clearPending();
    out.push('holdLong');
  } else if (held >= holdMs && !this.holdEmitted) {
    this.holdEmitted = 'hold';
    this.clearPending();
    out.push('hold');
  }
}

if (!this.covered && this.pendingAt !== null && now - this.pendingAt >= singleDelayMs) {
  const n = Math.min(this.taps.length, 3);
  this.clearPending();
  if (n >= 1) out.push(TAP_NAMES[n - 1]);
}
```

| Constant | Value | Effect |
|---|---|---|
| `coverRatio` / `releaseRatio` | `0.5` / `0.75` | hysteresis band; prevents chatter |
| `maxWaveMs` | `700` | slower than this is not a tap |
| `holdMs` | `900` | hold threshold |
| `longHoldMs` | `2400` | escalation threshold |
| `tapWindowMs` | `1500` | all taps of a double/triple must land in this window |
| `singleDelayMs` | `240` | how long a tap waits to see if it is part of a group |
| `minBaseline` | `12` | below this the sensor can't separate hand from room |
| `warmupSamples` | `6` | samples before the baseline is trusted |

Because the detector is pure — `push(lux, now)` and `tick(now)` return `WaveEvent[]` —
the whole gesture vocabulary is tested on a laptop in under a second:

```ts
// test/waveDetector.test.ts
const d = warm();                                     // 8 samples at 320 lx
const { events } = run(
  [
    [400, 640], [3, 720], [3, 780], [420, 860],       // tap 1

    [3, 1240], [3, 1300], [420, 1380],                // tap 3
  ],

// events === ['triple']  — not 'double' + 'wave'
```

## What the model is asked

`src/llmClient.ts` normalises any OpenAI-compatible base URL, `POST`s
`/chat/completions`, extracts JSON that may be wrapped in prose or fences, and surfaces
status codes as `LlmError`. No SDK, so the same code runs in the app bundle and in the
Node test harness.

```ts
// src/llmClient.ts (abridged)
export async function chat(target: ChatTarget, messages: Msg[], opts?: { maxTokens?: number }) {
  const t0 = Date.now();
  const res = await fetch(`${normaliseBaseUrl(target.baseUrl)}/chat/completions`, {
    method: 'POST',
    headers: { 'content-type': 'application/json', authorization: `Bearer ${target.apiKey}` },
    body: JSON.stringify({
      model: target.model,
      messages,
      max_tokens: opts?.maxTokens ?? target.maxTokens,
      temperature: 0.9,
      ...(target.reasoningEffort ? { reasoning_effort: target.reasoningEffort } : {}),
    }),
  });
  // ... throws LlmError(status, message) using the body's `error.message`
  return { text, ms: Date.now() - t0, usage };
}
```

**The `reasoning_effort` detail cost an hour of debugging.** `particle-1` thinks before
answering; with a 200-token cap the thinking ate the entire budget and every reply came
back empty or as a `400`. Sending `reasoning_effort: "none"` puts the whole budget into
the answer. `z-ai/glm-5.3-flash` rejects `"none"` outright, so `config.ts` treats an
empty value as "omit the field".

| Where | Function | What comes back |
|---|---|---|
| LGTM card | `proposeNext(history)` | `{"tool":"Read\|Write\|Edit\|Bash","detail":"<=52 chars","risk":"low\|medium\|high\|extreme"}` |
| LGTM after wave / hold | `reaction(p,'approve'\|'deny')` | one sentence about what just happened, or how it takes being told no |
| /COMPACT on mount | `seedContext()` | six load-bearing facts the agent is holding |
| /COMPACT on wave | `compactFact(facts)` | `{"from":"<fact>","to":"<=44 chars, subtly wrong>"}` |
| PANIC on wave | `diagnose(prior, seconds)` | the next line of false confidence, given elapsed time |
| /REPO on mount, wave | `triage(state, skip)` | `{"number":<real issue>,"why":"<=80 chars","action":"<=60 chars"}` |
| /REPO double | `plan(state, pick)` | `{"steps":["<=70 chars" x4]}` |
| /REPO triple | `roast(state)` | one true, specific line about the repo |
| /REPO holdLong | `standup(state)` | one line of what actually shipped, from the commit log |

Each task is a prompt plus a validator, and the validator is the contract:

```ts
// src/repoTasks.ts — triage rejects any issue number it was not shown
const number = Number(raw.number);
if (!open.some((i) => i.number === number)) fail(`issue #${raw.number} was never offered`);
```

That one line is why the `/REPO` tab cannot hallucinate a backlog: the model picks from
a list it was given, and anything else is an error the user sees. Output is validated
everywhere else too — wrong tool name, missing risk, a fact that was not in the list,
non-JSON prose: any of these throws, and the screen shows the error with tap-to-retry.

## The GitHub layer

`src/github.ts` makes three parallel reads — repo metadata, the 25 most recently updated
open issues/PRs, and the last 12 commits — and returns a typed `RepoState` with the
fetch duration attached, which is the number printed in the footer.

```ts
const [meta, issues, commits] = await Promise.all([
  get(`/repos/${repo}`),
  get(`/repos/${repo}/issues?state=open&sort=updated&direction=desc&per_page=25`),
  get(`/repos/${repo}/commits?per_page=12`),
]);
```

Everything downstream — triage, plan, standup, roast — is grounded in that snapshot.

## Setup

Requirements: Node 20+, an Android phone with a light sensor (S24 Ultra here), Expo Go
from the Play Store, and a [particle.ai](https://particle.ai) API key.

```sh
git clone https://github.com/harishkotra/palm-pilot.git
cd palm-pilot
npm install
cp .env.example .env      # fill in the particle.ai key + a read-only GitHub token
npx expo start -c         # -c is required after any .env change
```

Scan the QR in Expo Go. Same Wi-Fi is enough; for a remote phone use tunnel mode:

```sh
npx expo start --tunnel ngrok -c   # prints an exp://… URL you can open anywhere
```

Tunnel mode needs `@expo/ngrok` (already a dev dependency) and no Expo account — plain
`--tunnel` asks you to `npx expo login` for a signed URL.

Then, on the phone: wave a hand ~2 cm above the top edge, over the earpiece side. Tap
the model badge in the header to see what the app actually loaded and to run a live
round trip against it.

## Configuration

All configuration is build-time environment, read once in `src/config.ts`. Change a
value, restart with `-c`, reload the app.

| Variable | Default | Meaning |
|---|---|---|
| `EXPO_PUBLIC_LLM_BASE_URL` | `https://api.particle.ai/v1` | Any OpenAI-compatible base: particle global, `https://us.api.particle.ai/v1`, or `http://192.168.x.x:11434/v1` for Ollama |
| `EXPO_PUBLIC_LLM_API_KEY` | — | Bearer key. Placeholder only in `.env.example`; `.env` is gitignored and excluded from the zip |
| `EXPO_PUBLIC_LLM_MODEL` | `particle-1` | `deepseek-ai/deepseek-v41-flash-1017`, `z-ai/glm-5.3-flash`, or anything the endpoint lists |
| `EXPO_PUBLIC_LLM_REASONING_EFFORT` | `none` | `none` = no thinking tokens, whole budget to the answer; `low`/`medium` for better jokes; blank = omit the field |
| `EXPO_PUBLIC_LLM_MAX_TOKENS` | `200` | Cap for short replies; structural calls budget internally (300–700) |
| `EXPO_PUBLIC_GITHUB_REPO` | `pharos-hq/Helm-pwa` | `owner/name` for the `/REPO` tab |
| `EXPO_PUBLIC_GITHUB_TOKEN` | — | Read-only token (fine-grained: Issues + Pull requests + Contents read) |
| `EXPO_PUBLIC_GITHUB_API` | `https://api.github.com` | Point at a GitHub Enterprise host if needed |
| `EXPO_PUBLIC_DEBUG_GESTURES` | `0` | `1` shows the SIM row (×1/×2/×3/HOLD/HOLD+) for phones with no light sensor |

URL handling is deliberately forgiving, because the same app must talk to particle,
Ollama and LM Studio:

```ts
// src/llmClient.ts
export function normaliseBaseUrl(raw: string): string {
  let v = (raw || DEFAULT_BASE_URL).trim().replace(/\/+$/, '');
  if (!/^https?:\/\//i.test(v)) v = `http://${v}`;   // see test/parse.test.ts
  if (!/\/v\d+$/.test(v)) v = `${v}/v1`;
  return v;
}
```

  `useWaveHandler({...})`. That is the whole protocol — 150 lines and a prompt.
- **Add a gesture.** Extend `WaveEvent` and `DetectorConfig` in `src/waveDetector.ts`,
  add an assertion to `test/waveDetector.test.ts` *first* (the harness prints PASS/FAIL
  and exits non-zero), then wire the event through `waveBus.ts` and `useWave.ts`.
- **Add a repo task.** `src/repoTasks.ts` takes `RepoState` and returns a validated
  shape. Ground it in fields that exist; reject anything else.
- **Change the visual language.** `src/theme.ts` (palette) and `src/ui.tsx` (five
  components) are the whole surface area.

### Conventions this repo expects

- **No fallback content.** If a reply fails validation, render `ErrLine` with a retry.
  Never substitute a canned string — that is the one rule that would make the demo
  dishonest.
- **Pure logic stays pure.** Detectors and parsers take values and return values. If it
  needs React, it belongs in a hook.
- **New gesture ⇒ new assertion.** `npm test` must fail before the feature works.
- **Secrets stay in `.env`.** `EXPO_PUBLIC_*` is inlined into the bundle at build time;
  never commit a key, never put one in a screenshot, revoke tokens after demos.
- **Respect the sample cadence.** Android's `LightSensor` emits every ~80 ms; anything
  tuned against a 60 fps assumption will feel wrong on device.

### Pull requests

Small, one-mode PRs land fastest. Include: what you changed, the command output that
proves it (`npm test`, `npm run demo`, or a 5-second screen recording), and — for
anything gesture-related — the lux sequence you tested with. If you cannot test on an
Android device, say so; `npm run demo` output is acceptable evidence for detector and
prompt changes.

## Honest limits

- **Ambient-light sensing has no direction.** You cannot detect "swipe left". Duration
  and repetition are the whole vocabulary, which is why `holdLong` exists.
- **Bright rooms are the enemy.** With a baseline below the ~12 lux floor the detector
  refuses to arm rather than firing randomly.
- **iOS cannot do this.** `expo-sensors` exposes no `LightSensor`; the SIM row exists
  for that case and for stage fallback.
- **Gestures are tested as data, not on glass.** The detector is proven against real lux
  sequences; the physical wave is verified by a human, not CI.

## Key handling

`.env` is gitignored and excluded from the packaged zip. `EXPO_PUBLIC_*` values are
inlined into the JS bundle at build time, so this pattern is right for a demo on your
own phone and wrong for anything you ship to a store — for that, proxy the calls through
a server and keep both the model key and the GitHub token off the device. Use a
read-only GitHub token and revoke it when the demo is over.
