# Palm Pilot

A touchless demo for people who spend their day clicking **Allow** on an AI agent.

Your hand over the top edge of the phone is the input. No touch, no screen press —
the ambient-light sensor sees the room go dark for as long as your palm is there,
and how long — and how many times — it stays dark is the gesture.

Every line the app shows is generated by `particle-1` while you watch, and the
`/REPO` tab reads a real GitHub repo over the network before it asks the model
anything. There is no scripted content and no fallback copy: no key, no GitHub
token, or a bad reply means you see an error, not a joke.

## The four modes

| Tab | The joke | Gestures |
|---|---|---|
| **LGTM** | You approve everything your agent proposes without reading it | wave = approve · double = auto-approve loop · hold = deny · bold holdLong = new session |
| **/COMPACT** | Compaction quietly destroys the context you spent an hour building | wave = compact a fact · double = re-seed · triple = three compactions in a row · hold = pin |
| **PANIC** | The agent is stuck and will never know why | wave = next line · double = two turns · triple = four turns · hold = abandon |
| **/REPO** | The agent triages your actual backlog | wave = next pick · double = plan it · triple = roast the repo · hold = refresh from GitHub · holdLong = standup from real commits |

Each action is one model call, printed with its real latency and token count.

## Five gestures, one sensor

| Gesture | How you do it | Event |
|---|---|---|
| wave | quick pass, under 0.7 s | `wave` |
| double | two passes, both inside a 1.5 s window | `double` |
| triple | three passes in the same window | `triple` |
| hold | hand parked ≥ 0.9 s | `hold` |
| holdLong | same hand, kept there past 2.4 s | `holdLong` |

Taps are held back for 240 ms before they are named, which is what lets a third
pass turn a double into a triple instead of firing two events. `hold` and
`holdLong` are a single gesture that escalates: LGTM denies at 0.9 s and resets
the whole session if you simply don't move your hand.

## Setup

```sh
cp .env.example .env     # particle.ai key + a read-only GitHub token
npm install
npx expo start -c        # -c is required after changing .env
```

Scan the QR with **Expo Go** on the S24 Ultra. `expo-sensors`, `expo-audio` and
`expo-haptics` all ship inside Expo Go, so there is no build step. For a phone that
isn't on the same Wi-Fi: `npx expo start --tunnel -c`.

## Configure everything in `.env`

Every value is read once at build time. Change one, restart with `npx expo start -c`,
reload. Tap the model badge in the header to see what the app actually loaded and to
run a live round trip against it.

| Variable | Meaning |
|---|---|
| `EXPO_PUBLIC_LLM_BASE_URL` | Any OpenAI-compatible base. Particle global `https://api.particle.ai/v1`, US-only `https://us.api.particle.ai/v1`, or `http://192.168.x.x:11434/v1` for Ollama |
| `EXPO_PUBLIC_LLM_API_KEY` | Bearer key. Placeholder only in `.env.example`; `.env` is gitignored and excluded from the zip |
| `EXPO_PUBLIC_LLM_MODEL` | `particle-1`, `deepseek-ai/deepseek-v41-flash-1017`, `z-ai/glm-5.3-flash` — or any model the endpoint lists |
| `EXPO_PUBLIC_LLM_REASONING_EFFORT` | `none` suppresses thinking tokens so the whole budget goes to the answer. Use `low`/`medium` for better jokes, or leave blank for models that reject the field |
| `EXPO_PUBLIC_LLM_MAX_TOKENS` | Cap on short replies (proposal, reaction, diagnosis, triage). Structural calls get their own budget internally |
| `EXPO_PUBLIC_DEBUG_GESTURES` | `1` shows the SIM row (×1/×2/×3/HOLD/HOLD+) for phones with no light sensor. Default `0`: gestures only |
| `EXPO_PUBLIC_GITHUB_REPO` | `owner/name` for the `/REPO` tab |
| `EXPO_PUBLIC_GITHUB_TOKEN` | Read-only token (fine-grained: Issues + Pull requests + Contents read). Enough to list issues and commits |
| `EXPO_PUBLIC_GITHUB_API` | Defaults to `https://api.github.com`; point it at a GitHub Enterprise host if you have one |

## What the model is asked

| Where | Function | What comes back |
|---|---|---|
| LGTM card | `proposeNext(history)` | `{"tool":"Read\|Write\|Edit\|Bash","detail":"<=52 chars","risk":"low\|medium\|high\|extreme"}` |
| LGTM after wave / hold | `reaction(p,'approve'\|'deny')` | one sentence about what just happened, or how it takes being told no |
| /COMPACT on mount | `seedContext()` | six load-bearing facts the agent is holding |
| /COMPACT on wave | `compactFact(facts)` | `{"from":"<fact>","to":"<<=44 chars, subtly wrong>"}` |
| PANIC on wave | `diagnose(prior, seconds)` | the next line of false confidence, given elapsed time |
| /REPO on mount, wave | `triage(state, skip)` | `{"number":<real issue>,"why":"<=80 chars","action":"<=60 chars"}` |
| /REPO double | `plan(state, pick)` | `{"steps":["<=70 chars" x4]}` |
| /REPO triple | `roast(state)` | one true, specific line about the repo |
| /REPO holdLong | `standup(state)` | one line of what actually shipped, from the commit log |

`/REPO` never invents a repo: `src/github.ts` fetches `/repos/:repo`, the open
issue/PR list and the last 12 commits, and `triage` rejects any issue number that
was not in that list. Output is validated everywhere else too — wrong tool name,
missing risk, a fact that was not in the list, non-JSON prose: any of these throws,
and the screen shows the error with tap-to-retry instead of making something up.

## How the detector works

`LightSensor` fires every 80 ms. `src/waveDetector.ts` learns the ambient baseline,
treats a drop below `max(1.5, baseline × 0.5)` as *covered*, and classifies on release:

- covered < 700 ms → a **tap** (1 = wave, 2 = double, 3 = triple, inside 1.5 s)
- covered ≥ 900 ms → **hold**; still covered at 2.4 s → **holdLong**
- 700–900 ms → deliberately silent

`tick(now)` is what names deferred taps and escalates a long hold; it is called on
the same 80 ms stream. Tuning constants live in `DEFAULTS`. On iOS `expo-sensors`
has no `LightSensor`, so the readout stays at 0 and you need
`EXPO_PUBLIC_DEBUG_GESTURES=1` to drive it by touch.

## Key handling

`.env` is gitignored and excluded from the packaged zip. `EXPO_PUBLIC_*` values are
inlined into the JS bundle at build time, so this pattern is right for a demo on your
own phone and wrong for anything you ship to a store — for that, proxy the calls
through a server and keep both the model key and the GitHub token off the device.
Use a read-only GitHub token and revoke it when the demo is over.
